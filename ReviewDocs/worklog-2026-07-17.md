# Work Log — 2026-07-17

Godot strategy game: placeable, resource-producing **buildings** on their own tilemap layer, a
building-info popup, and the map's raw resources moved from drawn dots onto a real tile layer.

## New files (authored)

| File | What it does |
|---|---|
| `Systems/Game/Buildings.cs` | Holds both classes: `Building` — one placed building (`BuildingType {Farm,Mine,Well,Forestry}`, its tile `Location`, its **own** `Stockpile`, and `Produce()` adding one tick of its output at the matching `GlobalConfig` rate) — and `Buildings`, the registry keyed by tile (`Place` / `At` / `All` / `ProduceAll`). Pure logic; painting the tile is the UI's job (same split as `Roads`/`RoadPlacer`). |
| `Systems/Game/Tiles.cs` | Catalogs turning a type into its tileset source id: `ForBuilding` → buildings.tres, `ForResource` → resources.tres (both 0/1/2/3 in enum order, atlas (0,0)). The one place code points at those tilesets. |
| `UI/BuildingUI.cs` | Script on the `BuildingPanelContainer` scene node — the building popup. Fetches its `VBoxContainer/Header` + `{Grain,Iron,Water,Wood}Label` children, fills them from the building's stockpile (`ShowBuilding` / `Refresh`), and is click-and-drag movable like the city panel. |
| `tilesets/buildings.tres` | TileSet with the 4 building placeholder textures as sources 0–3. |
| `tilesets/resources.tres` | TileSet with the 4 resource placeholder textures as sources 0–3. |
| `Images/Placeholders/*.png` | 8 flat-colour 64×64 placeholders — buildings as bordered squares (Farm green, Mine slate, Well cyan, Forestry dark green), resources as circles matching the old dot colours (grain yellow, iron gray, water blue, wood brown). ~0.4–0.6 KB each. |

## Modified

- `Systems/Game/Main.cs` — creates the `Buildings` registry; wires `buildings.ProduceAll()` into the tick; hands `buildings` + the `BuildingsLayer` to `UIManager`; `ResourceMap` now receives the `ResourcesLayer` to paint onto.
- `Systems/Game/ResourceMap.cs` — scatters deposits as before, but **paints them as tiles on `ResourcesLayer`** (via `Tiles`) instead of drawing coloured circles in `_Draw`. Skips painting with a console note if that layer has no tileset yet (deposits are still recorded).
- `UI/UIManager.cs` — added the building UI: a row of **toggle** build buttons (one per type, in a `ButtonGroup` so only one is armed); left-click the map to place the armed building (`Buildings.Place` + paint `BuildingsLayer`); left-click a placed building to open the **popup** listing its stored resources, refreshed each tick (the popup itself now lives in `BuildingUI`). Removed the stray "answer this" comment on the class.
- `Scenes/main.tscn` — assigned `buildings.tres` → `BuildingsLayer` and `resources.tres` → `ResourcesLayer`.

## Removed

- `BordersLayer` node (and its `BorderHighlight.tres` reference) from `main.tscn` — nothing in code touched it and it held no tiles. Its `.tres` file is left orphaned on disk.
- `Systems/Game/Building.cs` → folded into `Buildings.cs`; `BuildingTiles.cs` + `ResourceTiles.cs` → folded into `Tiles.cs`. One tiny class per file wasn't earning its keep, and it matches how `Resources.cs` already holds both `ResourceType` and `Resources`.

## Scene / layer layout

- `0zTileMapLayer` (terrain)
  - `RailroadLayer` (roads)
  - `ResourcesLayer` (resource tiles) ← `resources.tres`
    - `BuildingsLayer` (building tiles) ← `buildings.tres`

`BuildingsLayer` is nested under `ResourcesLayer` on purpose: a child layer draws **above** its
parent, so buildings sit on top of the resource tiles.

## Controls (new)

| Input | Action |
|---|---|
| **Build button (panel)** | Toggle: click to arm that building type, click again to disarm |
| **Left-click (armed)** | Place the armed building on the clicked tile |
| **Left-click a placed building (not armed)** | Open its stored-resources popup |
